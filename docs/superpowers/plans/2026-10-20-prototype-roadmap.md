## Границы проверки

B разделён на B1/B2, чтобы проверить самое дорогое предположение до расширения интерфейса. B1 — MediaEngine, защищённый выбранный источник, встроенное окно, минимальные controls и ранний bundle/native gate. B2 после gate — полный набор горячих клавиш, auto-hide, buffer timeline, внешние SRT/ASS, Drag & Drop и интеграция защищённого loopback Range. Наличие B1-плана не означает готовности B или нативной проверки.

A не доказывает декодирование, NAT traversal, интернет-подключение или запуск установщика. B не доказывает передачу данных между сетями. C не доказывает нативный рендер. Только D вместе с отчётами B и C позволяет принять технический прототип по архитектуре.

Критерии D сохраняются: direct и принудительный TURN; macOS ARM64 и Windows x64; MP4/MOV/MKV; исходные дорожки; большой файл и seek без полной загрузки; ≤250 мс на согласованном стабильном стенде в течение 10 минут; восстановление после seek/reconnect за 5 секунд; закрытие прекращает доступ. Ранний bundle в B запускается без отдельно установленных mpv/Rust/Node; подпись и updater относятся к релизному этапу.

## Работа агентов

Метод уже выбран пользователем: агенты с руководствами Everything Claude Code, исполняемые средствами Codex; Superpowers задаёт порядок работы. Для A: исполнитель каждой задачи, независимый review соответствия плану, затем review качества/безопасности. ECC planner участвует в декомпозиции, architect — в межмодульных решениях, security-reviewer — в авторизации и сетевых границах. Роли TDD/code-review подключаются из того же зафиксированного источника перед соответствующей работой.

Рабочая копия `/workspace/Branch` уже изолирована cloud-задачей. Дополнительный worktree не создаётся. Задачи, меняющие общий контракт, исполняются последовательно. Независимые B/C можно делегировать параллельно после фиксации API ядра. Новый технический блокер отражается в плане и отчёте, а не заменяется имитацией успешного результата.

## Источники выбора зависимостей

20.10.2026 через официальные crates.io endpoints проверены опубликованные стабильные версии: axum 0.8.9, Tauri 2.12.4, webrtc 0.21.1, libmpv2 6.0.0. Это сведения для планирования, не подтверждение совместимости этих библиотек между собой. В A используется только axum; WebRTC/libmpv требуют отдельных проверок API и лицензий в планах B/C. Cargo.lock закрепляет фактически разрешённые зависимости после утверждения плана и первой установки.
