# План C: совместный просмотр через интернет

Дата: 22.10.2026. Статус: реализация начата; готовность не подтверждена.

Основание: [утверждённая архитектура](../specs/2026-10-20-watch-together-design.md), [PRD](../../requirements/2026-10-20-watch-together-prd.md) и [дорожная карта](2026-10-20-prototype-roadmap.md). Пользователь выбрал подключение через интернет из разных сетей и уточнил, что у всех участников уже есть один и тот же видеофайл.

## Цель и границы

Хост создаёт авторитетную комнату в приложении на своей машине. Каждый участник выбирает локальный видеофайл; Branch сверяет SHA-256 целиком и допускает в комнату только точное совпадение. Видео не передаётся. Через WSS идут только короткие команды и состояния. Хостовый `RoomServer` применяет команды и формирует авторитетные snapshots. Приложение само запускает TLS listener на TCP 8787, открывает порт через UPnP и определяет внешний IPv4 адрес; сертификат закреплён в приглашении. Отдельные серверные программы не нужны. TURN и WebRTC не нужны.

## Проверенные изменения

- Добавлены `MediaFingerprint`, SHA-256 выбранного файла и проверка изменения файла во время вычисления отпечатка.
- `RoomHandle::join_with_media` сверяет отпечаток до выдачи сессии.
- Создан `crates/network`: capability-приглашение в fragment URI, WSS signaling, сверка verifier и отпечатка до допуска гостя, пересылка playback intents хосту и snapshots гостям.
- Ограничения broker: 64 KiB на сообщение, 4 гостя, 10 попыток входа за минуту, 128 комнат и 512 соединений; idle-комната закрывается через 120 секунд.
- В desktop добавлен встроенный WSS listener на всех IPv4 интерфейсах, с эфемерным сертификатом и pinning его DER в приглашении. UPnP-модуль открывает и продлевает порт, удаляя mapping при выходе приложения. Отдельный `signal-server` оставлен для локального администрируемого сценария.
- `SignalClient` предоставляет независимые асинхронные send/receive через ограниченные очереди.
- `RoomHandle::apply_action` назначает время на стороне авторитетной комнаты, чтобы гость не мог прислать собственные часы.

## Состояние реализации

- Host runtime связывает `RoomHandle` с WSS: регистрирует комнату, подтверждает гостя только после локальной admission-проверки, принимает действия, обновляет room state и публикует snapshots. Соединение посылает heartbeat и удаляет гостевую сессию при отключении.
- Guest runtime подключается по ссылке, отправляет SHA-256 локального файла, ждёт одобрения хоста, передаёт действия и получает только авторитетные snapshots.
- Desktop UI предоставляет запуск собственного сервера, ввод публичного IP/DNS имени хоста, ссылку-приглашение, подключение гостя, статус и выход. Play, Pause, Seek и Speed проходят через комнату; snapshots применяются к локальному плееру. Выбор другого файла во время комнаты заблокирован.
- Проверки: сборка frontend, Rust `cargo check`, 5 network тестов, 39 room-server тестов и 14 тестов выбранного файла прошли. В полном media-stream прогоне один существующий транспортный тест `transport_rejects_headers_over_8192_bytes` упал, когда peer закрыл TCP соединение во время записи; остальные прошедшие наборы дали 24/25. Устройство и Интернет-сценарий не проверялись.
- `scripts/native/build-macos.sh --check-plan` вернул `source_plan_verified`; SDK и `.app` пересобраны для macOS ARM64. Старые локальные SDK outputs сохранены в `target/native/aarch64-apple-darwin/previous-build-2026-10-22`.
- Bundle verifier отклоняет распространение с `inventory_incomplete`: `license_inventory_complete` остаётся `false`, а target `artifacts` не объявлены готовыми. Результаты сборки и текущие hashes записаны в инвентарь без поднятия readiness-флагов.

## Критерии готовности

- Нельзя присоединиться с другим файлом либо неверным приглашением.
- Гостевые команды не меняют snapshot напрямую: их проверяет и применяет хостовый `RoomServer`.
- Хост и гости получают авторитетный snapshot и локально применяют Play, Pause, Seek и Speed.
- Токены не попадают в логи; очереди, соединения, сообщения и срок жизни комнаты ограничены.
- В интерфейсе видны создание/закрытие комнаты, копирование ссылки, ввод ссылки и понятные статусы.
- Сборка приложения завершается. Тестирование на устройствах и проверка реального интернета остаются отдельными шагами.

## Внешняя зависимость

Для разных сетей сервер работает на Mac хоста, а приглашение содержит адрес и TLS сертификат сервера. Приложение автоматически открывает TCP 8787 через UPnP и обнаруживает публичный адрес. Если UPnP выключен/не поддерживается или подключение за CGNAT, прямой хостинг недоступен. Межсетевое подключение ещё не принято end-to-end.
