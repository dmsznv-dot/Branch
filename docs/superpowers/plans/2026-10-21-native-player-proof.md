# B1: Native Player Proof — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Получить небольшой локальный плеер со встроенным libmpv и проверить, годится ли Tauri для видео и прозрачных элементов управления на macOS ARM64 и Windows x64.

**Architecture:** Rust `media-engine` владеет декодером и типизированными командами; нативная OpenGL-поверхность располагается под прозрачным WebView в одном окне Tauri. Выбранный открытый файл передаётся libmpv через зарегистрированный read-only stream callback, без передачи пути в JavaScript. Сначала проверяется композиция окна и ранний bundle; расширение UI и подключение сетевого источника следуют после этой проверки.

**Tech Stack:** Rust 1.99.1 / edition 2024; Tauri 2.12.4; React + TypeScript + Vite + Tailwind; libmpv 0.41.0 / client API 2.5; узкая FFI-обёртка над `libmpv2-sys` 4.0.1; CGL/NSView на macOS, WGL/HWND на Windows. Frontend: Node 24.19.0/npm 11.9.0, React/ReactDOM 19.3.1, TypeScript 7.0.2, Vite 8.3.4, plugin-react 6.1.2, Vitest 5.0.5, Tailwind + plugin 4.3.3, Tauri JS API 2.12.4/CLI 2.12.3; Testing Library React16.3.3/jest-dom7.0.1, jsdom30.1.3, @types/react и react-dom19.3.0. Транзитивные зависимости закрепляются lock-файлами в задаче 3; опубликованные версии проверены, совместимость ещё предстоит проверить.

**Spec:** [утверждённый дизайн](../specs/2026-10-20-watch-together-design.md), §2–3, §5, §7–9; [уточнение интерфейса](../../requirements/2026-10-20-interface-notes.md); [общая последовательность A–D](2026-10-20-prototype-roadmap.md).

## Global Constraints

- Обязательные целевые ОС: macOS Apple Silicon и Windows 10/11 x64. Linux — среда разработки, не целевая проверка native surface. macOS Intel — отдельная дополнительная проверка.
- Контейнеры: MP4, MOV, MKV. Минимум кодеков: H.264, HEVC, VP9, AV1; для каждого фиксировать программный/аппаратный путь. ProRes проверяется отдельно. Отсутствие подходящего GPU не должно запрещать software decode.
- Полноэкранный режим: десять переходов fullscreen/window и перенос между дисплеями разного DPI; исходное соотношение сторон сохраняется.
- Тестовый bundle должен запускаться на чистых целевых ОС без отдельно установленных mpv, Rust или Node. Подпись, notarization и updater — последующий релизный этап.
- Источник — только явно выбранный файл. libmpv запускается без пользовательских конфигураций, скриптов и автоматического открытия соседних файлов; вложенные плейлисты и ссылки на невыбранные ресурсы запрещены.
- Нет generic IPC для путей, URL, shell, mpv-команд или свойств. Привилегированный WebView загружает только локальный UI; минимальные capabilities и CSP. Имена файлов и метаданные — недоверенный текст.
- Громкость, mute, fullscreen, аудио и субтитры локальны. Команды общего воспроизведения в будущей комнате обязаны проходить RoomServer; B1 работает в явно обозначенном локальном режиме.
- Внешний процесс mpv не является результатом встраивания; HTML video не подменяет libmpv. До целевых испытаний Tauri остаётся предварительным выбором, Qt 6 — предусмотренный архитектурой запасной вариант.
- Метод исполнения уже выбран: Codex-агенты с инструкциями ролей ECC и порядком Superpowers. Работать в существующей изолированной копии `/workspace/Branch`, без дополнительного worktree.
- Сохранять инварианты A и воспроизводимость его проверок. Ни комнаты, ни подключение к другу, ни участники не изображаются работающими до C/D.

## Review Focus

1. Быстрый выбор A → B при задержанных событиях декодера: старый кадр, ошибка или метаданные не заменяют состояние B. Тест задачи 2 `stale_generation_is_discarded`.
2. Закрытие окна во время заблокированного чтения или render callback: отмена разблокирует reader; callback не обращается к уничтоженным Rust/GL данным. Тесты задачи 2 `shutdown_cancels_read_before_free` и задача 3 `close_during_render`.
3. Поддельный MP4/плейлист, соседний файл, MOV dref или HTTP-ссылка внутри источника: невыбранные ресурсы не открываются. Негативные тесты задачи 2 `references_are_not_followed`.
4. Длинное Unicode-имя и HTML-подобные метаданные: интерфейс остаётся доступным, разметка не исполняется; путь не попадает в IPC/логи. Тест задачи 3 `metadata_is_plain_text`.
5. Минимизация, нулевой размер поверхности, дробный DPI и потеря фокуса: нет деления на ноль, падения/зависания; размер viewport после восстановления актуален. Тест задачи 3 `surface_geometry` и native-проверка задачи 4.

## Граница этого плана

Это **первая часть B**, а не завершение всего B или MVP. Самостоятельный результат — локальный embedded player для технической проверки, с открытием файла, play/pause, seek, скоростью, выбором встроенных дорожек, fullscreen и диагностикой декодера. Интерфейс намеренно минимален и следует компоновке PDF.

После положительного native gate отдельный план **B2** добавляет законченные горячие клавиши, auto-hide, buffer timeline, внешние SRT/ASS, Drag & Drop и интеграцию с аутентифицированным loopback Range из A. Эти требования остаются в дорожной карте. Интернет-комнаты и синхронизация реальных декодеров — C/D. B1 не объявляется завершением B при отсутствии целевых машин или отчёта об их испытании.

## Зафиксированные технические решения

- Использовать libmpv **render API**, `vo=libmpv`, с отдельной native-поверхностью и прозрачным дочерним WebView, а не `wid` с отдельным окном mpv. Объединённое окно управляет fullscreen и resize.
- Для явного parent window + child WebView требуется Tauri feature `unstable`. Применение ограничить модулем `window.rs`, закрепить Tauri; не распространять эти API на медиаядро. Для macOS прозрачность требует `macos-private-api`; допустимость этой зависимости отдельно отмечается перед релизом.
- CGL на macOS; WGL на Windows — небольшой начальный вариант без дополнительной поставки ANGLE. На Windows использовать `hwdec=auto-copy`: аппаратный декодер с копированием кадра допустим, zero-copy и D3D11 interop не обещаются. Фактический путь выводится из свойств mpv. При проблемах производительности ANGLE/EGL исследуется отдельно, до изменения базового решения.
- Не использовать `libmpv2::Protocol` для отзываемого источника: исследованный wrapper 6.0.0 не предоставляет `cancel_fn`. Собственная небольшая FFI-граница сохраняет userdata до завершения mpv core и реализует отмену. Не добавлять `unsafe impl Send/Sync` без документированного доказательства владения и отдельного review.
- Главный источник имеет непрозрачный URI `branchmedia://<generation UUID>`. URI не содержит путь или секрет и принимается callback только при точном совпадении с текущей зарегистрированной записью. Callback читает уже открытый descriptor, а не повторно открывает путь.
- Применять `access-references=no`, `autoload-files=no`, `config=no`, `load-scripts=no`, `ytdl=no`, `input-default-bindings=no`, `input-vo-keyboard=no`, `osc=no`, `osd-level=0`, отсутствие IPC socket и дискового кэша. Главный demuxer — lavf с `demuxer-lavf-o`/`format_whitelist=mov,matroska`; MOV `enable_drefs=0`, `use_absolute_path=0` устанавливать только для MOV/MP4, не передавать MOV-only параметры Matroska; дополнительные форматы не включать по содержимому файла. Проверить применимость и успешную установку каждого параметра к закреплённому mpv: отказ настройки завершает инициализацию с ошибкой.
- Upstream mpv 0.41.0 блокирует дополнительные `AVFormatContext::io_open` при `access-references=no`; у FFmpeg MOV по умолчанию отключены external drefs. Это не sandbox процесса: отрицательные испытания ресурсов обязательны, и их провал блокирует gate.
- У event worker и renderer разные mpv client handles одного core. Render context создаётся, используется и освобождается на одном render thread с текущим GL context; native hierarchy меняется на UI thread. Callback только сигнализирует о работе, не вызывает mpv синхронно и не ждёт UI. Никаких GL-вызовов из JavaScript.

**Общие типы задачи 1**, используемые следующими задачами:

- `PlaybackGeneration(Uuid)` — непрозрачный идентификатор открытия, новый при каждом выборе.
- `SelectedFile::open(path: &Path) -> Result<SelectedFile, EngineError>`; `display_name(&self) -> &str`; `len(&self) -> u64`; `read_at(&self, offset: u64, dst: &mut [u8], cancel: &CancellationToken) -> Result<usize, EngineError>`. Конструктор вызывается только доверенным Rust-кодом выбора. Полного пути в структуре после открытия нет. `Debug` редактирован, сериализация отсутствует.
- `Track { id: i64, kind: TrackKind, title: Option<String>, language: Option<String>, selected: bool }`; `TrackKind::{Audio,Subtitle}`. ID относится только к текущему поколению.
- `EngineCommand::{SetPaused(bool), SeekToMs(u64), SetSpeed(Speed), SetVolume(u8), SetMuted(bool), SelectAudio(i64), SelectSubtitle(Option<i64>), Stop}`. Скорость берётся из существующего `shared_protocol::Speed`, громкость 0–100. На этой границе нет произвольной строки команды или свойства.
- `PlayerStatus::{Idle,Loading,Paused,Playing,Buffering,Ended,Failed}`; `EngineSnapshot { generation: PlaybackGeneration, status: PlayerStatus, position_ms: u64, duration_ms: Option<u64>, speed: Speed, volume: u8, muted: bool, tracks: Vec<Track>, decoder: Option<DecoderInfo> }`.
- `DecoderInfo { codec: String, hwdec: Option<String>, video_output: String }` — наблюдаемая диагностика, не секрет. Не определять hardware decode по наличию GPU или только по запрошенной настройке.
- `EngineError::{Unavailable, UnsupportedMedia, InvalidCommand, Busy, SourceChanged, Cancelled, DecoderFailed, ShutdownTimeout}`; стабильный публичный код, без путей, URI, метаданных или raw libmpv error text.

Reader ограничивает один read размером `media_stream::CHUNK_BYTES` (65 536), не читает фильм целиком.

## Task 2: Реальный libmpv worker, безопасные callbacks и headless decode

**Files:** Create `src/mpv/*`, `src/bin/media-probe.rs`, `tests/{worker,policy,native_decode}.rs`; modify package features/lock; create `scripts/setup-player-linux.sh`, fixture script и начало `native-player.md`/`native-dependencies.json`.

**Interfaces:** Consumes Task 1. Produces:

- `EngineHandle::start(mode: EngineMode) -> Result<EngineHandle, EngineError>` — `EngineMode::{Headless,Native}`, feature `native-mpv`; очередь команд ёмкостью 64, latest-state `tokio::sync::watch`.
- `open(&self, file: SelectedFile) -> Result<PlaybackGeneration, EngineError>`; `command(&self, generation: PlaybackGeneration, command: EngineCommand) -> Result<(), EngineError>`; `subscribe(&self) -> watch::Receiver<EngineSnapshot>`; `shutdown(self) -> Result<(), EngineError>` — async методы, кроме subscribe; start также async. Переполненная очередь возвращает `EngineError::Busy`, не растёт; старое поколение не меняет состояние нового.
- `RenderEndpoint` — одноразово передаваемый render-client handle того же mpv core; `take_render_endpoint(&mut self) -> Result<RenderEndpoint, EngineError>`. Headless режим его не требует. Контракт завершения: renderer освобождён раньше последнего mpv handle, source userdata живёт до остановки core.
- `MpvRenderer::create(endpoint: RenderEndpoint, resolver: GlResolver) -> Result<MpvRenderer, EngineError>`; `render(&mut self, target: RenderTarget) -> Result<(), EngineError>`; `report_swap(&mut self)`. `GlResolver = fn(&CStr) -> *const c_void`; `RenderTarget { fbo: i32, width: i32, height: i32, flip_y: bool }`. Renderer не Send/Sync; GL context текущий на вызывающем render thread.

- [ ] **Step 1: Write worker/policy RED.** `stale_generation_is_discarded`: открыть A, затем B; завершение/error/property A не меняет snapshot B. `shutdown_cancels_read_before_free`: тестовый reader ждёт отмены; shutdown отменяет, дожидается reader/callback, освобождает userdata ровно один раз и не оставляет worker. `typed_commands_only`: NaN/Inf от mpv, неизвестный track ID и volume 101 отклоняются; `SeekToMs(20_000)` при duration10_000 вызывает native seek10_000, а при неизвестной duration сохраняет 20_000, не превращая её в 0. В тестах использовать внутренний test double очереди/событий native backend; публичный production API остаётся типизированным.
- [ ] **Step 2: Run RED.** `cargo test -p media-engine --test worker --test policy`; увидеть конкретные падения поколения/порядка освобождения/проверок, затем реализовать их.
- [ ] **Step 3: Implement worker and FFI.** В `ffi.rs` RAII client/event/node wrappers; документировать каждый unsafe block и время жизни C pointers. В `stream.rs` read/seek/size/close/cancel callbacks: cap 65 536 bytes, checked i64 offsets, EOF=0, ошибка отрицательная; panic не пересекает FFI; cancel callback только сигнализирует и не блокируется. Регистрация существует до прекращения использования core; не освобождать userdata по простому drop guard при ещё зарегистрированном callback. На quit сначала отменить reader, остановить и join renderer, остановить mpv/event worker, затем освободить userdata/file. Общий timeout 5 секунд; timeout не оправдывает free данных, которые ещё использует native code. Probe изолирует возможное зависание отдельным процессом; timeout фиксируется как ошибка.
- [ ] **Step 4: Implement fail-closed policy.** В `policy.rs` применить зафиксированные настройки до init/load; запретить unsupported options, произвольные открываемые URI и любые команды вне enum. `demuxer=lavf` и `demuxer-lavf-o` format whitelist разрешают только mov/matroska, `access-references=no`; тестировать реальные отказавшие обращения, а не только список настроек. Секреты и raw mpv logs не сохранять/не транслировать в UI.
- [ ] **Step 5: Prepare actual decode fixtures and environment.** Сначала `setup-player-linux.sh` устанавливает доступные development headers/libmpv и FFmpeg (версию зафиксировать), проверяет client API через `mpv_client_api_version`; unsupported API/option — явная ошибка. Этот setup не называется проверкой целевого native bundle. Скрипт FFmpeg генерирует собственные короткие CC0 test patterns: MP4/H.264 с `moov` в конце, MKV с двумя аудио и встроенными SRT, MOV/H.264; дополнительные HEVC/VP9/AV1 — отдельные файлы. Использовать зафиксированный FFmpeg build/source и записать команды/хеши/лицензии. Если encoder отсутствует, генерация соответствующей фикстуры завершается ошибкой, без подмены другим кодеком. Fixtures в `target/player-fixtures`, не коммитить бинарные фильмы. `media-probe --file <fixture> --headless` должен дождаться `video-params/w > 0`, `video-params/h > 0`, `estimated-frame-number >= 2` и позиции >=100 ms за максимум 10 секунд (`EngineMode::Headless`: `vo=null`, `ao=null`, software decode), прочитать duration/tracks, seek, pause, все шесть скоростей; не использовать elapsed time как доказательство decode. Вывод — только фиксированные event names и безопасные кодек/числовые поля.
- [ ] **Step 6: Run real security/decode GREEN.** `cargo test --locked -p media-engine --features native-mpv --test native_decode -- --test-threads=1`. `references_are_not_followed`: M3U/PLS под видом .mp4, MOV с внешним dref, matroska ordered chapter reference и невыбранный `branchmedia://...` не открывают spy-файл и локальный HTTP listener; конфиг/скрипт и соседние subtitles не загружаются. Сам spy должен быть проверен positive control вне запертого decoder. Unknown codec → `UnsupportedMedia`; выбранный файл изменён → `SourceChanged`; файл недоступен при первичном выборе → `Unavailable`. - `set_fullscreen(value: bool) -> Result<(), PublicError>`;
- `player_snapshot() -> PlayerView`; событие `player-state` содержит тот же `PlayerView`.

`PlayerView` отражает snapshot + basename и локальный режим; `PlayerCommandDto` — serde DTO того же `EngineCommand` с `deny_unknown_fields`, tagged enum, без расширяемого property map; position/duration передаются как существующий `WireU64`/decimal strings (duration nullable), ID — строками. Не включать full path, source URI или raw error. `PublicError { code: EngineError }`. Выбор файла из IPC со строковым аргументом не предоставлять. Tracks — текущие реальные tracks mpv.

## Порядок исполнения и агентские проверки

Задачи 1 → 2 → 3 → 4 последовательны: источник, decoder lifetime и surface владеют общими контрактами. На каждую — свежий исполнитель с ролью ECC `tdd-guide`, затем review соответствия плану и review качества; для FFI/policy/capabilities добавить ECC `security-reviewer`, для surface — `architect`. После задач — whole-branch review. В конце обновить существующий environment config draft новыми setup/start инструкциями, сохраняя прежние поля и core-only путь; проверить их исполнением. Публикация конфигурации остаётся действием пользователя, без заявления о fresh-instance replay. Инструкции ролей берутся из официального ECC commit `30b68924ae9729159f44326aa3134b1d9d67c0e2`, как в A; это применение руководств агентами Codex, не заявление об установленном Claude Code.

При отсутствии target OS продолжать независимые Linux tests, frontend и подготовку bundle recipes/CI; фактические native и clean-machine строки оставить BLOCKED. Не заменять их PNG-макетом, отдельным окном mpv или фиктивным UI-плеером. Выбор метода исполнения пользователем сохраняется; до кода требуется только review этого конкретного плана по writing-plans.
