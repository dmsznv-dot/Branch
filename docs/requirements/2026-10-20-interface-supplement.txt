04 / Синхронизация и правила управления

    Хост хранит актуальное состояние и нумерует изменения (revision).
    p   lay / pause / seek / speed → проверка прав → новая revision → рассылка всем участникам
    Клиенты оценивают задержку и сдвиг часов. При входе и переподключении получают актуальную позицию.



Отклонение от общего таймкода: начальные пороги коррекции из ТЗ


    0–100 мс                                100–500 мс                                          >500 мс
    Без коррекции                           Плавная коррекция скорости                          Перемотка к целевой позиции


Пороги — настройки для испытаний, не результат измерений. Цель MVP: рассинхронизация ≤250 мс в стабильной сети; сверка каждые 1–2
секунды.


    Синхронизируется для всей комнаты                                          Настраивается отдельно у каждого
    Пауза · запуск · таймкод · скорость просмотра                              Громкость · fullscreen · аудиодорожка · субтитры
    Команды исполняются с учётом прав комнаты.                                 Буферизация одного участника не ставит всех на паузу.

Условия реализации
Файлы передаются без обязательной полной загрузки и без транскодирования. HTTP Range и WebRTC — разные транспортные модели: не
считать их интеграцию готовой без прототипа. Доступ разрешён только к выбранному файлу; запросы авторизуются.
